# Qualcomm/QNN model shortlist (VI/EN)

Research snapshot: 2026-10-15. Scope is offline Vietnamese/English speech recognition and text translation for VoxBridge. Qualcomm catalog/model cards, owner model cards, and Qualcomm SDK/Workbench documentation were checked; no credentials, downloads, compile/profile jobs, or device tests were used.

## Recommendation

For an Android Qualcomm path, audition Qualcomm's **Whisper-Small-Quantized (W8A16)** against the current PhoWhisper Vietnamese and Whisper Small English baselines. It is a first-party Qualcomm AI Hub recipe based on multilingual `openai/whisper-small`, and its model card explicitly describes multilingual transcription/translation. This is the clearest single model candidate for a shared VI/EN QNN path. It does not establish that Vietnamese accuracy beats PhoWhisper; preserve PhoWhisper as the VI accuracy control until the same local corpus is scored.

For translation, Android currently uses **ML Kit VI↔EN**. Keep the existing **OPUS-MT vi→en + en→vi** as the Mac baseline and an offline-package candidate pending quality and device acceptance. Qualcomm AI Hub's catalog has four OpusMT directions (en↔es and en↔zh), but no Vietnamese direction. Its general Workbench accepts ONNX for compilation, so exporting these existing graphs and attempting QNN is a technically supported generic route, not a Qualcomm model recipe or a guaranteed successful compile. If OPUS quality fails the product corpus, M2M100-418M is a Vietnamese-capable, MIT-licensed research fallback; it has 418M parameters and the official Hub lists a 1.94 GB weight file, with no Qualcomm recipe. It is not the first Android choice absent quality evidence that justifies this footprint.

## Export, artifacts, and where to measure

For the Qualcomm Whisper Small quantized recipe, the official model CLI path is:

```bash
qai-hub-models export whisper_small_quantized --target-runtime voice_ai --precision w8a16 --device "Samsung Galaxy S26"
```

Use an exact device listed for the recipe and your actual phone; the example device is listed by Qualcomm for the model. Qualcomm model-specific, already-built releases are also enumerated in `release-assets.yaml`; assets are keyed by chipset/runtime/precision and include the QAIRT tool version. Treat them as device/build-specific inputs, not interchangeable generic weights. [Recipe README](https://github.com/qualcomm/ai-hub-models/blob/main/src/qai_hub_models/models/whisper_small_quantized/README.md), [export settings](https://github.com/qualcomm/ai-hub-models/blob/main/src/qai_hub_models/models/whisper_small_quantized/export.py), [release assets](https://github.com/qualcomm/ai-hub-models/blob/main/src/qai_hub_models/models/whisper_small_quantized/release-assets.yaml).

For custom OPUS-MT or PhoWhisper graphs, current Workbench docs accept ONNX. The current QNN context-binary workflow is compile/link (including optional embedding into ONNX), rather than the older `qnn_context_binary` compile-target path that Workbench release notes say was removed in September 2026. QNN context binaries are OS-agnostic but SoC/HTP-specific and designed for NPU execution; a precompiled QNN ONNX package contains an ONNX wrapper plus its `.bin` context and uses ONNX Runtime's QNN Execution Provider. A QNN DLC is the more hardware-agnostic alternative, with device preparation at load time. Keep ordinary ONNX artifacts for CPU fallback. [Compile formats and context binaries](https://workbench.aihub.qualcomm.com/docs/hub/compile_examples.html), [compile/link API](https://workbench.aihub.qualcomm.com/docs/hub/generated/qai_hub.submit_compile_and_link_jobs.html), [Workbench release notes](https://workbench.aihub.qualcomm.com/docs/hub/release_notes.html), [QNN format FAQ](https://workbench.aihub.qualcomm.com/docs/hub/faq.html).

**Mac CPU and Qualcomm device results answer different questions.** The M2 can run regular ONNX/ORT CPU exports locally and is useful for functional/quality baselines. It cannot run Qualcomm HTP/QNN or predict NPU latency. AI Hub Workbench compilation/profile uses hosted Qualcomm hardware and account access; those are remote device results. Final Android latency, memory, thermal behavior, compatibility, and CPU fallback require a physical target phone running the integrated app. Do not call a cloud-hosted profile a local Mac measurement or a validation of the app's end-to-end path. [Workbench overview](https://workbench.aihub.qualcomm.com/docs/), [Qualcomm AI Hub Models workflow](https://github.com/qualcomm/ai-hub-models#export-from-source-and-run-a-model-on-a-physical-device).

## Version and integration guardrails

- Qualcomm AI Hub Models' latest repository release at this snapshot is **v0.64.0** (2026-10-07). Workbench release notes report **QAIRT 2.50.0** added 2026-09-14. Pin the recipe/client and target QAIRT version in any future experiment; the model recipe's published artifact can have an older QAIRT build. [Release v0.64.0](https://github.com/qualcomm/ai-hub-models/releases/tag/v0.64.0), [Workbench release notes](https://workbench.aihub.qualcomm.com/docs/hub/release_notes.html).
- QAIRT supports Android arm64 toolchains for listed Qualcomm SoCs, but context-binary deployment is tied to the exact SoC target and runtime compatibility. Select the actual handset/SoC in the official device matrix and package matching Qualcomm runtime libraries. The reviewed public docs do not state one universal minimum Android API level for all QAIRT-supported devices; verify the chosen phone/SDK combination rather than inventing a global minimum. [QAIRT supported platforms and SoC table](https://docs.qualcomm.com/nav/home/QNN_general_overview.html?product=924033590759186372), [context-binary compatibility](https://workbench.aihub.qualcomm.com/docs/hub/faq.html).
- A QNN artifact can accelerate model graphs, not the entire VoxBridge pipeline automatically: audio framing/mel features, tokenization, autoregressive decode, beam search, and language/postprocessing still need integration and correctness checks. The AI Hub Whisper recipe uses Qualcomm-specific graph transformations, so its packaged model is not a drop-in replacement for the repo's three standard Whisper ONNX graphs without adapting the Android runtime.
- The follow-up downloaded the public frozen v0.64.0 precompiled SM8650 bundle and successfully profiled both graphs on Galaxy S24 Ultra/Android 14. Encoder `jgk62y2w5` and decoder `j57oed3qg` used NPU; see measured follow-up below. This does not establish app compatibility or model quality.

## Measured follow-up on 2026-10-15

Both hosted profiles succeeded, with 100 runs per graph. Encoder median **45.6435 ms**; decoder median **6.364 ms per token step**. All 1,894 encoder and 2,853 decoder trace nodes reported NPU. Profiler inference-peak estimates were **146.19 / 155.73 MiB**, not whole-app RSS; cold/warm-load memory peaks are separately retained in the compact evidence. Synthetic input profiles do not prove transcription quality or full-utterance latency. [Compact evidence and job URLs](../../submission/phase-3/evaluation/qualcomm-graph-profile.json).

The archive is pinned in [the manifest](../../config/models/qnn-whisper-small-sm8650.json). The original `release-assets.yaml` points to pre-release S3 keys which returned HTTP 403. The stable v0.64.0 public release path worked and its 285,196,969-byte archive and extracted payload hashes are recorded. This is a tested download path, not an assumption based on the catalog page.

The package metadata declares **ORT 1.30.0 / QAIRT 2.50.0.260828221209**. The app currently pins ORT 1.20.0; Maven Central listed QNN Android only up to 1.29.0 when checked. Therefore this package has **not** been silently staged in the app or marked deployable. The preparation gate rejects a declared 1.20.0 runtime or wrong SoC; matching metadata still needs native execution validation. [Working preparation/profile commands](../../model-tools-python/qaihub/README.md).

CPU quality control on the same 10 supplied Vietnamese WAVs found **Whisper Small 19/78 word errors (24.36%) versus PhoWhisper Base 9/78 (11.54%)**. Do not switch Vietnamese to the generic multilingual model merely to share one NPU package. Encoder-only dynamic INT8 PhoWhisper reduced median CPU ASR from 452 to 333 ms, but errors increased to 10/78; it was not promoted. These small exposed diagnostic sets have unreviewed references and are not acceptance scores.

Android currently uses **ML Kit** translation; OPUS is the local Mac comparator and an explicit offline-package option, not the current Android backend. OPUS tokenizer case handling was corrected and 6/6 source token sequences now match the official Marian tokenizer, fixing two repeated-No upper-case-input examples. MT still drops a sentence in another example, and changing the tokenizer does not fix ASR errors. New Android TTS is not integrated: the selected Nano bridge currently runs on Mac only.
