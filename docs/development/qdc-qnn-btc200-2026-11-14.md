## EnViT5 FP16 recovery in this session

The first floating QNN encoder produced severe errors/repetition (first full smoke case hit192tokens). Diagnostic hooks found encoder RMSNorm inputs up to2465.98; direct FP16 squares overflow above~255.9. The original model remains unchanged on disk. A separate export substitutes only the encoder RMSNorm algebra:

`x / sqrt(mean(x²)+eps)` → `(x/32) / sqrt(mean((x/32)²)+eps/1024)`.

Original weights are preserved; encoder output parity against original CPU ONNX passed all200BTC inputs, maximum absolute difference0.00010252. A test demonstrated old FP16 overflow failure, then the stable form passed FP32/FP16 reference tolerance. Recompiled encoder job `jgdmr2mlg`; original floating decoder `j5wrdx1zp` retained. Device smoke2/2 tokens matched original before the full200run. This fixes the broad encoder failure, but does not fix the remaining capped case.

## Benchmark implementation and controls

Standalone module `android/qdcbench`, separate package `com.voxbridge.qdcbench`. Device keeps cross/self KV and runs complete ASR greedy or MT beam2 loops; host handles original tokenizers, frozen ASR frontend, orchestration and scoring. One request per utterance. Forced ASR prompt `[50258,50278,50359,50363]`, EOT50257,199decoder positions. MT source64/target192/beam2, length penalty1, original EOS/early stopping. Too-long sources reject rather than truncate.

Java beam2 was checked against the pinned Transformers4.51.3 generator:

- Eight tiny T5/mBART full traces: per-step tokens, stop timing, final tokens.
- **All400 actual FP32 translations (200 VinAI +200 EnViT5): exact full-token equality**, using source ONNX logits to independently drive Java beam search. The observed QNN-vs-FP32 metric differences cannot be dismissed as an unverified replacement beam implementation.
- Tensor batch gather tests cover beam duplicate/reorder and invalid shape/index.
- Tensor protocol and scoring tests cover exact byte counts, float/int roundtrip, archive escape rejection, WER normalization/counting, incomplete-run labels and duplicate IDs.

Historical debug/host-driven results are retained separately. QDC's debug build remained dexopt `verify` even when the compile command returned success. Release APK is non-debuggable, signed with dev key; explicit `cmd package compile -m speed -f ...` verified status `speed`. ASR debug decode1819/2268ms improved to release720/1021ms with100/100 unchanged outputs. Do not combine those runtime measurements.

`device_decode_ms` is timed inside the phone from before encoder/preparation to completion of local decoding/beam/cache handling. It excludes host VAD/mel/tokenization, network, model loading and TTS. `graph_run_ms` is the sum of ORT run calls only. `wall_ms` includes SSH/ADB roundtrip and host work. Model loading and warmup are separate; first sentence is warmed then measured again as a scored record. Neither graph time nor host wall time proves an integrated<2s pipeline.

## Conclusion and next work

PhoWhisper-small QNN preserves WER on this dataset and now has an appropriate release-runtime measurement. Neither MT candidate's standalone complete decode currently fits a<2s whole-pipeline target: EnViT5p50 alone2.227s; VinAI3.161/5.301s. Native graph calls are much shorter, indicating substantial remaining work in cache transfer/reorder, buffer allocation/JNI and decode orchestration. That overhead must be measured and reduced, followed by repeat quality checks. VinAI VI→EN quality regression and the one EnViT5 capped case must remain explicit blockers for final selection. No final app integration/full pipeline deadline claim is made.
